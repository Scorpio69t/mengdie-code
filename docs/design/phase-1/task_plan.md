## 关键问题

1. M1 的最小“能日用”闭环是什么？
2. 哪些能力必须在 macOS 与 Windows 上同时通过？
3. M1 与 M2 的事件持久化、resume、Patch Journal 如何保持清晰边界？
4. 如何在不引入完整 TUI 和 daemon 的前提下提供可用终端体验？
5. 如何将任务拆成可独立验收、可回归的实现单元？

## 已确定决策

- 第一阶段对应 M1“能日用”，M0 是进入条件。
- macOS 与 Windows 是 Tier 1 双一等平台；Linux 保持支持与 CI 覆盖。
- M1 使用单进程、本地优先架构，不实现 daemon、Web、记忆、resume 和自动 Git 提交。
- M1 使用简单终端交互层，不提前引入完整 TUI 框架。
- 所有修改和命令必须先通过 Policy 与 Approval；平台差异由适配层隔离。
