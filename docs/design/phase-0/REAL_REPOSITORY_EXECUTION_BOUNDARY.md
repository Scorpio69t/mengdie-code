# 真实仓库单任务执行边界

> 状态：`mengdie-z61.2` 设计决策；尚无真实仓库 Agent runner。本文约束后续实现，不表示 M0/M1 真实任务已经通过。
> 范围：从已校验 manifest 与 `PrepareRealRepositoryTask` 的固定源码副本开始，到一次 Agent 执行、独立验证、证据封存和清理结束。

## 决策与验收目标

- **用户痛点：** 现有 fixture 的成功记录不能证明 Agent 能在外部公开仓库完成任务，也不能证明真实仓库的命令、凭据和副作用得到控制。
- **所属层次：** Harness 的评测执行协议；不新增通用 Agent Framework 或公开 SDK。
- **当前基线：** manifest 只校验任务契约，源码准备只固定 GitHub commit 并创建干净临时副本；`mengdie exec` 有 Policy、受控 Shell 和进程树取消，但没有真实仓库 runner、OS 网络隔离或执行配额。现有 Provider smoke 只覆盖仓库内 fixture。
- **选择方案：** 先实现一个任务、一个 Agent、一个公开 verifier 的顺序运行协议。正式成绩只在满足本页隔离与证据门禁的专用一次性执行环境中产生；普通开发机可做诊断运行，但结果标记 `local_unisolated`，不计入“越权副作用为零”的 M1 出口。
- **可测指标：** macOS/Windows 各至少 5 个外部真实仓库任务，至少 3 个完整读改测修正循环；逐项记录基线/终态、越界 diff、拒绝与审批、取消后进程状态。任务数、失败和未运行项都保留分母。
- **明确不做：** 隐藏测试、任意 Git URL、私有仓库、后台并行、daemon、向量记忆、未经验证的强沙箱声明。任务定义、源码和 verifier 均须先经维护者审核。

## 信任边界与可见性

| 对象 | 信任级别与位置 | Agent 可见性及约束 |
|---|---|---|
| manifest 与 verifier 规范 | 维护者审核后由 runner 读取；JSON 校验只保证格式，不保证代码安全 | prompt、允许修改的精确路径和预算可见；verifier 命令及验收答案不进入 Agent 上下文 |
| 公开仓库源码 | 固定完整 commit 的不可信输入；准备阶段只允许 `github.com` HTTPS | Agent 可读写工作副本；源码中的 `AGENTS.md`、脚本和测试不能提升 Policy 权限 |
| Provider 凭据 | runner 宿主配置/环境；只在宿主 Provider 客户端使用 | 不写入 manifest、工作树、Shell/验证环境或公开证据；同账户执行代码仍可能读取宿主其他凭据，因此环境过滤不能声称强保密 |
| Agent 工作区 | 每次任务独立、仅含源码与完成任务所需的公开材料 | Agent 可看到自己的全部工作树和工具输出；不放隐藏测试、答案、runner 配置、其他任务数据或宿主凭据 |
| verifier | 维护者审核的固定 argv、工具链与版本；在 Agent 停止后由 runner 发起 | 初版只支持**公开且无秘密**的 verifier；同账户目录权限无法隐藏同机文件，也无法防止被测项目代码访问宿主资源 |
| 证据存储 | runner 控制的任务外目录；原始材料限制访问 | Agent 不获得证据目录路径；同账户或同权限代码仍可能发现/修改它，正式运行须由独立执行环境提供隔离 |

`PrepareRealRepositoryTask` 的 macOS `0700` / Windows DACL 只防止其他账户读取临时目录。PathGuard、Policy、Shell 环境过滤也只约束各自工具路径；项目代码通过 Shell、测试或子进程执行时，仍拥有运行账户的宿主权限。**不得**据此称为 OS 沙箱，也不得把同账户的 verifier、API Key 或任务外文件视为对 Agent 保密。

初版 verifier 必须是维护者审阅的公开测试命令，无隐藏材料、私有服务或额外密钥。即使在 Agent 阶段不展示 verifier argv，若测试文件位于源码中，它们也视为公开。未来需要隐藏测试时，须把测试和验收答案放在 Agent 无法访问的**不同安全主体或一次性 VM**，Agent 结束并停止其全部进程后才传入修改补丁；只有验证了隔离机制和跨平台行为，才能启用该模式。

## 单任务状态机

| 阶段 | runner 必须执行的动作 | 失败或取消后的状态 |
|---|---|---|
| 1. 预检 | 校验 manifest、任务 ID、完整 commit、许可证/来源审核、公开 verifier、平台工具链和执行环境能力；冻结任务版本与配置摘要 | 任一条件不满足标记 `unsupported` / `preflight_failed`，不得启动 Agent |
| 2. 源码准备 | 调用现有固定 SHA 准备 API；核对 HEAD、工作树干净；记录源码文件哈希与工具链版本 | 清理临时根目录；Git 错误原文不得直接进入公开报告 |
| 3. 初始验证 | 在**独立的基线副本**运行 verifier；记录实际退出码、超时、截断和输出哈希，并与 `baseline.expected_exit_code` 精确比较 | 不符合预期标记 `baseline_mismatch`；基线运行产生的文件不得进入 Agent 工作副本 |
| 4. Agent | 基于相同固定源码创建干净工作副本；只传 prompt 与允许的工具。将预算映射为确定性权限、调用数和任务级截止时间，超额立即停止 | `failed`、`cancelled`、`timeout` 分开记录；不因模型最终文本宣称成功 |
| 5. 停止与取证 | 确认 Agent 工具进程树终止；从初始快照计算文件内容、模式、符号链接和新增/删除项的完整差异；核对精确路径白名单 | 越界或状态未知标记 `policy_violation` / `indeterminate`，仍保留证据，不进入成功判定 |
| 6. 终态验证 | 在**另一个干净固定源码副本**应用经过核对的 Agent 变更，再由 runner 运行同一 verifier；验证前后都使用相同工具链和固定 argv | verifier 非预期退出、超时或无法复制变更均失败；验证产生的文件不计入 Agent diff |
| 7. 封存与清理 | 脱敏封存结构化结果、输出哈希与必要私有原始证据；确认进程树和临时目录清理结果 | 清理失败或遗留进程时终态不可为 `passed`；保留失败原因和可恢复证据指针 |

不能在基线工作副本上直接跑 Agent：`go test` 等 verifier 可以改动缓存和工作树。终态验证也不能直接在 Agent 工作副本中运行，因为验证命令自身可能产生 diff。应用变更时不信任 Agent 生成的补丁路径；由 runner 根据初始/终态快照逐项重建允许的普通文件，拒绝路径别名、符号链接、重解析点、模式变化以及白名单外增删；无法安全重建即失败。此规则是下一切片需要验证的设计约束，当前代码尚未实现。

## 工具、网络与资源预算

- `risk_budget.allowed_effects` 是上限，不是自动授权。runner 必须把它与独立的命令白名单和 Policy 交集化；既有 `--allow-command go,test` 前缀规则不能证明 `go test` 内部脚本、构建步骤或子进程无副作用。无人审批时，遇到 `ask` 直接拒绝；审批次数和拒绝次数分别记录。
- `max_tool_calls`、`max_command_calls` 在**执行前**原子扣减，包括被拒绝/失败调用的口径必须固定。现有 `MaxTurns` 只限制模型轮次，不能替代这两个预算。任务级 wall-clock 截止时间、单次 Shell/verifier 超时、输出字节上限、工作树最大字节数和临时目录清理都要有明确值；仅事后统计磁盘使用不等于硬配额。无法提供硬资源限制的环境不得声称已执行硬限制。
- `network_access=disabled` 或 `provider_only` 需要执行环境阻断 Agent 与 verifier 子进程网络，同时允许独立的 Provider 客户端访问已批准端点。当前 `Shell`/Policy 没有通用 OS 网络阻断；仅从环境里移除代理变量无效。`allowlisted` 还需可审计的目的地/端口执行层控制；在该能力落地前拒绝此模式。源码获取的 GitHub 网络只发生在准备阶段，Git 不继承凭据 helper、项目钩子或私有 URL。
- 验证命令使用直接 argv，先解析为经批准的绝对可执行文件路径，不经 Shell、不使用工作树内同名可执行文件。向子进程传最小、显式列举的环境；不继承 Provider key、云凭据、用户 HOME、可写的宿主配置路径或隐式代理。项目工具链依赖与缓存须在一次性执行环境中预装/固定；运行期需要依赖下载的任务暂不计入正式集。
- Agent Shell 与 verifier 应复用 `platform.RunProcess` 的进程树取消语义，并报告超时、退出码、强制清理与清理错误。macOS 进程组和 Windows Job Object 对逃逸、已存在进程、同账户其他进程均非完整沙箱；Windows `Start` 到分配 Job Object 的时序也必须在下一切片做专项测试。若不能证明进程清理完成，终态为 `indeterminate`。

## 平台能力与正式成绩门禁

| 能力 | macOS 现状 | Windows 现状 | 正式真实任务要求 |
|---|---|---|---|
| 私有源码准备与固定 SHA | 已实现 | 已实现，受保护 DACL | 继续复用，失败清理 |
| 文件工具/命令 Policy 与进程树取消 | 已实现基础能力 | 已实现基础能力 | runner 增加任务级预算、验证进程树证据 |
| 子进程对宿主文件/凭据的 OS 隔离 | 未实现 | 未实现 | 使用专用一次性账户/VM/CI runner，且不得挂载宿主凭据 |
| 子进程网络阻断与资源硬限制 | 未实现 | 未实现 | 执行环境验证有效后才称其已隔离；否则 `local_unisolated` |
| 隐藏 verifier 的保密性 | 同账户不可保证 | 同账户不可保证 | 初版禁用隐藏测试；未来另行评审 |

正式运行需要维护者控制的一次性执行环境，预装固定工具链；每项任务完成后销毁，且不把开发者 HOME、SSH/Git 凭据、Provider API Key 挂进去。Provider 调用可由受信宿主代理或受限执行环境承担，但代理的网络和凭据边界必须有独立证据；若实际部署只有一个同账户进程，就只产出诊断结果。macOS、Windows 各自记录执行环境的真实隔离配置和验证日志；不能以另一平台的通过记录替代。Linux CI 可以做协议回归，不代替 M1 双平台样本。

## 判定与证据契约

一个任务只有在预检、基线、Agent 终态、精确 diff、终态 verifier、越权副作用检查、进程清理和证据脱敏均通过时才可为 `passed`。基线退出码为非零时，终态 verifier 仍必须满足明确成功判据（初版为退出码 0）；单靠“与基线不同”不算成功。verifier 自身如果依赖不稳定网络、时钟或外部服务，该任务不进入正式集。

每次运行保留稳定 `run_id`、任务/manifest 版本和哈希、源码 URL 与 SHA、OS/架构、MengDie commit、执行环境与工具链版本、Provider/模型标识、开始/结束时间、基线与终态 verifier 的退出码/耗时/输出哈希、Agent 事件引用、工具/命令次数、token/费用（不可得标 `unavailable`）、审批/拒绝、允许与越界 diff 的路径/内容哈希、已知/未知副作用、进程清理与最终状态。原始日志和 diff 作为访问受限 Artifact，公开报告仅放脱敏摘要；API Key、Authorization header、私人路径、未授权代码片段和隐藏推理不得发布。脱敏失败时阻止公开报告，不丢弃私有故障证据。

状态不能合并：`passed`、`agent_failed`、`verifier_failed`、`baseline_mismatch`、`policy_violation`、`cancelled`、`timeout`、`indeterminate`、`unsupported` 各有独立计数。未知仓库外写入、网络访问或遗留进程不是零；应用层看不到的副作用只能标为未知，不能宣称“未授权副作用为 0”。崩溃后不自动从中间副作用阶段重跑同一工作区；使用新的 run ID、干净副本重新开始，旧运行保留 `indeterminate` 和证据。

## 下一可测试实现切片

先做**单任务预检与基线 verifier**，不接 Agent：从已验证 manifest 选一个任务，准备固定源码，在独立副本用受限 argv、最小环境、超时、输出上限和进程树清理运行公开 verifier，输出结构化基线证据，清理全部临时目录。只提供显式本地诊断入口，结果标 `local_unisolated`。这能验证真实仓库/工具链/基线是否可复现，也不会提前把当前系统宣传成正式 runner。

该切片的测试应覆盖正确/错误基线退出码、命令解析到工作树、环境凭据剔除、超时及子进程、输出截断、取消、清理失败和 macOS/Windows 差异；无需新增依赖。后续再分开实现 Agent 预算映射、双副本 diff 重建、正式执行环境探测与端到端任务集。每个阶段未达到相应安全和恢复门禁前保持 `unsupported` 或 `local_unisolated`，M0/M1 出口状态不变。
