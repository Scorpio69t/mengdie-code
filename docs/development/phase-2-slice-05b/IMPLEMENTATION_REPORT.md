# P2-05B 可恢复上下文预算与滚动摘要实施报告

> 状态：已实现，待 PR 审核
> 日期：2026-08-11
> Beads：`mengdie-1b3`

## 用户痛点与切片边界

此前 Runtime 会在估算请求超过 `max_context_tokens` 时直接失败；长任务虽然已有完整私有上下文和 Artifact Store，却没有把这些事实转换为可持续工作的有界模型输入。本切片完成“预算溢出 → 生成摘要 → 先持久化 → 继续模型调用 → 可安全恢复”的最小闭环。

摘要只服务当前 Session，不是长期记忆，也不具备事实权威。原始上下文仍由 `context_messages` 与 Artifact Store 保存。模型主动按需回填某一摘要区间、跨 Session/项目复用、向量检索和成本持久化不在本切片实现。

## 压缩与保留策略

- 系统提示、AGENTS.md 项目指令、Todo 始终在预算构建阶段重新注入，不进入可压缩区；
- 第一条原始用户任务始终作为锚点保留，最新用户任务及其后续消息不压缩，最近至少 8 条完整消息优先原样保留；
- 切点不能让 `tool` 结果脱离其 Assistant 工具调用；没有安全闭合区间或摘要请求本身无法放入同一模型窗口时 fail-closed；
- 摘要请求使用同一 Provider/模型，但不携带任何 tools 或工具选择字段，并使用固定协议 `mengdie-context-summary/v1` 和有界输出。输出必须通过严格 JSON 字段校验，显式包含目标与约束、决策、已验证证据、未解决错误、Todo/审批/工具状态和继续指针；缺字段、未知字段、空目标或自由文本一律拒绝；
- 当前轮的副作用工具结果可能比允许恢复的内容更完整。Runtime 因此维护与私有账本逐条对齐的压缩来源镜像：正常模型调用仍能看到当前完整结果，摘要生成只能读取已允许持久化的恢复安全形式。

## 持久化与恢复

Migration 005 新增 `context_summaries`。每条滚动摘要记录 Session/Run/Command、原始来源 `source_start/source_end`、摘要正文及 SHA-256、实际生成模型、协议版本、压缩前估算和压缩后上界。来源区间只能单调前进，摘要写入时 Run 必须仍处于 `running`。

摘要生成成功后，Runtime 先验证它确实能让主请求回到预算内，再写入私有摘要，随后提交只含区间、预算、模型和协议版本的 `context.compacted` 公开事实；摘要正文和来源消息不进入 EventBus、TUI 或 JSONL。

Resume 仍先加载并核验全部原始上下文、Artifact、消息顺序和公开/私有边界，再校验最新摘要 SHA 与来源区间。有效时模型输入使用“首个原始任务 + 派生摘要 + 未压缩原始尾部”；摘要缺失时继续使用完整原始历史，摘要存在但损坏时拒绝静默恢复。

## 预算与约束保持评测

固定 Harness 构造 1 条原始任务、16 条长历史、1 条当前任务和 1 个进行中 Todo。未压缩主请求估算为 11,414 tokens；在 9,000 token 窗口内，摘要占位上界下的主请求为 8,959 tokens，单次主请求至少减少 2,455（21.5%）。模拟摘要调用使用 900 input / 80 output tokens，因此第一次压缩轮的估算总 input 为 9,859，仍比直接发送完整主请求少 1,555；后续轮次复用滚动摘要时不重复携带已压缩原文，收益继续累积。该数字是确定性估算与 fake Provider 用量，不冒充真实账单。

同一评测断言主请求仍包含原始任务、当前任务、进行中 Todo、系统安全提示和“摘要不是原始证据”的边界，并确认被压缩的私有历史不再进入主请求。另有测试证明摘要生成读取恢复安全消息镜像，而不是当前内存中更完整的副作用输出。
